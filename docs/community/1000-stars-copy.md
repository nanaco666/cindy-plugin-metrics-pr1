# Cindy 1000 ⭐ 里程碑文案包 / 1,000 Stars Copy Pack

> **状态**：社区素材（非工程规则），可自由取用、按渠道裁剪。
> **适用**：GitHub 公告、X / 微博 / 即刻 / 小红书、Discord 与微信社群、公众号、
> 网站与 README banner。
> **口径来源**：`README.md` / `README.zh-CN.md`、`docs/product-rules/core-product-principles.md`、
> `i18n/GLOSSARY.md`（Agent、Skill、Harness、插件等术语沿用既有裁决）。

## 0. 使用须知

- 占位符：`{{stars}}`（实际星数）、`{{contributors}}`（贡献者人数）、`{{prs}}`
  （已合入 PR 数）、`{{date}}`、`{{release}}`（版本号）。发布前逐一替换成**核实过的
  真实数字**，宁可不写，也不要凑数。
- 语气基调：**功劳归社区，不自夸产品**。星标是社区的投票，不是团队的成绩单。
- 不要写的话：不承诺未发布的功能时间表；不拿星数对标其他项目；不暗示星标=用户数、
  下载量或收入；不做「求 star」式话术（庆祝里带乞讨会掉价，CTA 一律指向贡献与共建）。
- 事实红线（都能在 README 里核到）：客户端 Apache-2.0 开源、本仓只含桌面端与手机端
  及共享 packages、服务端在独立仓库、首批兼容 Claude Code 与 Codex 两套 Harness、
  可用官方服务 / 已有 Coding Plan / 自带 API key / 本地模型、有本地模式（无需登录）。

## 2. GitHub 公告长版（Discussions / Release notes）

### 2.1 中文

**标题**：`一起点亮 1000 颗星：Cindy 客户端开源的第一个路标`

```markdown
今天，Cindy 客户端仓库的 star 数越过了 1000。

我们把这颗星理解成一句话：**「这个方向值得做。」**

一年前把客户端开源的时候，我们其实没有把握——一个「开箱即用的 AI Agent」
到底需不需要开源？后来是你们替我们回答的：有人在 issue 里贴出连我们自己都
没复现过的边界情况，有人为了一个换行缩进提了 PR，有人把 Cindy 接到我们从
没想过的内部系统上，还有人只是默默点了颗星——它们都算数。

**这 1000 颗星背后是：**

- {{contributors}} 位贡献者，{{prs}} 个已合入的 PR
- 每一个 commit 都带着 DCO 签名，没有 CLA，改进属于所有人
- 桌面端与手机端、Claude Code 与 Codex 两套 Harness，都在同一个公开仓库里演进

**为什么我们坚持开源客户端：**

Cindy 运行在你自己的电脑上，用你本地的文件和已登录的应用。这样一个东西，
凭什么让你信任？我们能给出的最好答案就是：**源码摊开在这儿，自己看。**
开源不只是看得见，更是改得动——她记住的规矩（Memory）、她做事的方法
（Skill）、她够得到的系统（MCP）、她的功能与外观（Plugin），乃至她本身
（Source），都可以被你改写。

**接下来，欢迎从这些地方加入：**

- 想动手：`CONTRIBUTING.md`，从 `good first issue` 开始
- 想提需求或吐槽：开一个 issue，越具体越好，能复现的 bug 是最好的礼物
- 想让更多人用上：把你的使用场景写出来分享给别人，比任何广告都管用

第 1000 颗星只是一个路标。真正好玩的部分——把 Cindy 变成**你的** Cindy——
才刚刚开始。

谢谢你们。🌟
```

### 2.2 English

**Title**: `1,000 stars: a marker on the road, not a finish line`

```markdown
Today the Cindy client repository crossed 1,000 stars.

We read every one of them as the same sentence: **"this is worth building."**

When we open-sourced the client, we honestly weren't sure an
"AI agent that works out of the box" needed to be open at all. You answered
that for us — with edge cases in issues we had never reproduced ourselves,
with a pull request over a line-wrap indent, by wiring Cindy into internal
systems we never imagined, and sometimes just by quietly starring the repo.
All of it counts.

**Behind those 1,000 stars:**

- {{contributors}} contributors and {{prs}} merged pull requests
- Every commit signed off under the DCO — no CLA, improvements belong to everyone
- Desktop and mobile, Claude Code and Codex harnesses, all evolving in one public repo

**Why the client is open source:**

Cindy runs on your own machine, using your real files and your logged-in apps.
Why should you trust software like that? The best answer we have is simple:
**the source is right here — read it.** Open source means more than visible;
it means changeable. Memory, Skills, MCP, Plugins, and the source itself are
all yours to reshape.

**Where to jump in:**

- Want to build: start with `CONTRIBUTING.en.md` and the `good first issue` label
- Want to complain: open an issue — the more specific the better, and a
  reproducible bug is the best gift you can send us
- Want to help others: write up how you actually use Cindy. That beats any ad we could run.

Star #1,000 is a marker on the road. The interesting part — making Cindy
*yours* — is just getting started.

Thank you. 🌟
```
